# 任务联动验证

适配基线：DeepSeek Harness 0.2.1-rc.2。此轮新增功能版本为 1.1.0-beta.1；公开 v1.0.0 安装地址仍对应旧版。

## 桌面端操作

1. 关闭 DeepSeek Harness，在当前源码目录执行 `node build.mjs`、`node install.mjs`，然后重新启动应用。
2. 打开一个开发会话，在右侧栏选择「小说阅读器」，确认任务状态下方是当前会话名称。
3. 提交一条实际需求，打开小说阅读；开启顶部「联动专注」。执行过程中应正常滚动、搜索和切章。
4. 等待本轮正常完成，应出现完成提醒，正文被专注页覆盖。此时目录、搜索、摘记也不能查看小说内容；关闭提醒不会解锁。
5. 在原开发会话提交新需求。被 dsh 接受后，小说应自动恢复到原章节与段落位置。
6. 分别检查等待工具确认、手动停止和执行出错，状态应清楚区分，不能显示「任务已完成」。
7. 切到另一个会话，确认标题和状态跟随当前会话，小说不回到书架；其他会话及子任务的完成不会替当前会话触发完成。
8. 关闭「联动专注」后重复一次正常完成，应有提醒但不锁定正文。

## 本地验证

执行 `npm run build`、`npm test`、`npm run check`、`npm pack --dry-run`。

启动静态预览后打开 `preview.html?task-demo=1`。顶部按钮只产生本地模拟事件，采用与桌面集成相同的适配器；可验证完成锁定、自动续跑维持锁定和新需求解锁。模拟操作不代表已经验证过真实桌面任务流。

## 实现边界

- 正常完成取决于 dsh 持久事件 `turn/end`，且 reason.kind 必须是 `completed`；仅运行指示灯变为停止不足以判断成功。
- 这是一次开发轮次的结束，不代表整个项目验收通过。失败、取消、中断、输出上限和阻塞是其他状态。
- 新需求以 dsh 已接受的真实用户消息或用户队列插入为准。乐观输入框回显、失败的发送尝试、自动目标续跑与子会话消息不能解锁。
- 完成后锁定策略只在当前插件生命周期内保存序号证据；重载会重新读取当前可用历史。极端历史截断无法证明所有用户输入，辅助专注不承诺防止手工绕过。
- 顶部开关、导入和外观设置始终可用。锁住的正文使用 inert、ARIA 隐藏与视觉遮罩阻止交互，并在解锁时恢复阅读锚点。
- 不发送系统通知，不读取需求正文，不提交任务，不把书籍传给模型。侧栏关闭后不会用后台常驻进程强制通知。

## 本轮检查记录

已对照本机打包的 Session Controller / UI Session 公开接口实现，并完成自动回归与浏览器模拟验证。真实 Electron 桌面中的模型执行、确认弹窗及完整任务生命周期仍需按上述步骤进行联调；不要将模拟器的结果视作官方兼容审核。
